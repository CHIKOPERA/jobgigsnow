Mobile-first design system

A job board that loads before you blink

Every component here is specified at 360 px first, scales to desktop with the same tokens, and ships inside a 90 KB critical path. Accessible states are part of the component, not a follow-up ticket.

Fast by default

Thumb-reachable

Primary actions live in the bottom 40% of the viewport. 48 px minimum hit area, 8 px minimum gap.

One scan path

Tokens, not values

04

Accessibility & performance

Ship-blocking checklist

✓Every interactive element reaches 48×48 including padding.
✓Focus ring visible on canvas, surface and dark button.
✓Card is one link; the save control is a separate button outside it.
✓Result count announced in a live region after filtering.
✓Layout survives 200% zoom and 320 px width without horizontal scroll.
✓All motion respects prefers-reduced-motion.

Budget per route

HTML + critical CSS≤ 24 KB
JS, first load≤ 60 KB
Font subset, one weight axis≤ 28 KB
Images above the fold0
Interaction to next paint< 120 ms

Company logos are text initials until the detail route — that alone removes 30+ requests from the list view.

Naming rules+

Tokens are role-named, never value-named. Add a role before adding a colour; if two roles want the same hex, that is correct.

Handoff format+

Source of truth is tokens.json (W3C DTCG). CSS variables, Swift and Kotlin outputs are generated — never hand-edited.

Adding a component+

Ship it with the five states shown here — default, focus, pressed, loading, disabled — plus a 320 px screenshot and its byte cost.

Motion+

Two durations only: 120 ms for state, 240 ms for sheets. Easing cubic-bezier(.2,0,0,1). Nothing animates on first paint.
